# clowzy: تحديث الهوية ومراجعة الجاهزية

التاريخ: 25 سبتمبر 2026.

## طلب المستخدم والتعديل

اعتمد المستخدم اسم clowzy وألوانًا زرقاء داكنة مائلة للأسود. طُبقت الهوية على مكوّن العلامة، وصفحة الدخول والدعوة، وشاشة التحميل، وتذييل التطبيق، وعنوان المتصفح، والأيقونة، واسم ملف تصدير CSV من الخادم والمتصفح.

الألوان معرفة في بداية src/app/globals.css: خلفية #080f1c، أسطح #101b2d، لون إبراز #91bdf7، وأزرار #245bb0. حافظت الواجهات على العربية واتجاه RTL، مع عرض الاسم اللاتيني باتجاه LTR. الأخضر والأصفر والأحمر محصورة في الدلالات الوظيفية للحالة والنجاح والتنبيه والخطأ. احتُفظ بمعرفات قاعدة البيانات والجلسات وحسابات العرض القديمة كي تبقى البيانات والجلسات الحالية صالحة.

نسخة المصادر السابقة موجودة في work/clowzy-brand-before داخل جذر المهمة، خارج مجلد التطبيق. لا تشمل الأسرار أو قاعدة البيانات.

## التحقق

- npm run typecheck: نجح.
- npm run lint: نجح.
- npm run build -- --webpack: نجح؛ لا نشر خارجي ضمن هذا الأمر.
- npm test: تعذر بدء مشغل tsx بسبب منع إنشاء منفذ IPC في البيئة.
- node --import tsx --test tests/*.test.ts: نفذ الاختبارات نفسها مباشرة دون منفذ IPC؛ نجح 18 اختبارًا.
- تحليل CSS: كل متغيرات الألوان المستخدمة معرفة. اجتازت 11 ثنائية نص/خلفية أساسية نسبة 4.5:1؛ أدنى نسبة ضمنها 5.43:1. تباين حدود الإدخال مقابل خلفيتها 3.34:1. هذا فحص حسابي للوحة الأساسية، وليس تدقيق إتاحة شاملًا للصفحات.
- لا توجد مراجعة مرئية جديدة على الكمبيوتر أو الهاتف: أداة المتصفح رفضت زيارة 127.0.0.1:3100 بسبب رفض إذن المستخدم. لم يتم تجاوز الرفض بطريقة أخرى.

## الجاهزية الحالية

النسخة غير جاهزة لاستقبال مستخدمين حقيقيين في الإنتاج. عند مراجعة الشفرة الحالية:

1. src/app/api/[...path]/route.ts يقيد الخدمة إلى APP_MODE=demo ومضيف محلي، وتوجد مداخل حسابات تجريبية.
2. src/lib/store.ts يستخدم SQLite محليًا، ومزوّد البحث الافتراضي demoProvider. لا يزال تنفيذ البحث مرتبطًا بطلب المستخدم؛ لا يوجد عامل تشغيل مستقل مكتمل.
3. src/lib/demo-provider.ts يعيد جهات اتصال example.com ويقترح الفلاتر بكلمات مفتاحية، دون AI أو مزوّد بيانات حي.
4. تكامل Supabase للإنتاج وإرسال الدعوات آليًا واختبارات التحمل والاسترجاع والنشر الحي ما زالت مهامًا مفتوحة في tasks/plan.md وtasks/todo.md.

## المرشح الأول لمزوّد البيانات

FullEnrich مرشح أول للاختبار بسبب وجود Search API لاكتشاف جهات الاتصال، ثم Enrichment للحصول على البريد، وبرنامج reseller لتقديم البيانات داخل منتج مستقل. لا توجد تجربة حية أو موافقة ترخيص أو بيانات اعتماد للمزوّد ضمن هذا التعديل. التوصية مشروطة بعينة من القطاعات والبلدان الفعلية وباتفاق تجاري مناسب للعرض والتخزين والتصدير لمشتركي clowzy.

- نظرة عامة على APIs: https://docs.fullenrich.com/api/v2/general/introduction
- البحث: https://docs.fullenrich.com/api/v2/general/intro-search
- مكان API key وطريقة المصادقة: https://docs.fullenrich.com/api/v2/general/authentication
- حالات التحقق من البريد: https://docs.fullenrich.com/api/v2/general/email-status
- برنامج إعادة البيع وشروطه المخصصة: https://fullenrich.com/partners/resellers
- Apollo كبديل يحتاج أيضًا اتفاقًا لتقديم البيانات لمستخدمين خارجيين: https://docs.apollo.io/docs/developer-faqs
