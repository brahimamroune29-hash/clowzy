# clowzy — النسخة المحلية الأولى

تطبيق عربي متجاوب لعرض منصة Lead Generation الخاصة بالمشتركين. الاسم المعتمد حاليًا هو clowzy، بهوية زرقاء داكنة مائلة للأسود.

## التشغيل

يتطلب Node.js 22.13 أو أحدث.

1. شغّل npm install.
2. انسخ .env.example إلى .env.local إذا لم يكن الملف موجودًا.
3. أضف FULLENRICH_API_KEY إلى .env.local للتجربة الحقيقية، ثم شغّل npm run dev. لا تضع المفتاح في متغير NEXT_PUBLIC.
4. افتح http://127.0.0.1:3100.

للتشغيل بعد بناء محلي: npm run build ثم npm run start. يعمل الخادم على جهازك فقط.

من صفحة الدخول اختر «دخول كمشترك» أو «لوحة الأونر». يمكنك تجربة حساب مستقل بإنشاء دعوة من لوحة الأونر وفتح رابطها وتعيين كلمة مرور. أزرار تبديل الدور للتجربة المحلية فقط، وليست نظام صلاحيات إنتاجيًا.

## ما يعمل فعليًا

- حسابات محلية بكلمات مرور مجزأة، جلسات محفوظة على الخادم وملف تعريف ارتباط HttpOnly.
- دعوات تنتهي بعد 48 ساعة وتقبل مرة واحدة، رصيد يحدده الأونر، رابط استعادة وصول مدته ساعة.
- لوحة المشترك، فلاتر البحث، نتائج محفوظة وسجل بحث، تفاصيل جهة الاتصال، تصفية واختيار وتصدير CSV.
- دفتر رصيد دائم: حفظ البريد وخصم الكريدت داخل معاملة واحدة؛ قيد فريد يمنع البريد المكرر داخل حساب المشترك.
- عزل الحسابات في استعلامات الخادم؛ تحقق دور الأونر في كل إجراء إداري.
- لوحة الأونر: المشتركين، منح/تعيين/تصفير الرصيد مع السبب، تعطيل الحساب وإلغاء جلساته، الدعوات وسجل التدقيق.
- سجل تصدير، حسابات ملخصة من البيانات المحفوظة، تصميم مناسب للجوال والقائمة الجانبية.
- حماية طلبات التعديل بمصدر الطلب، تحديد عدد الطلبات، فحص المدخلات، وحماية CSV من صيغ جداول البيانات.

## ما هو تجريبي أو غير متصل

- بيانات البداية القديمة وهمية وتحمل وسم «تجريبية». تبقى محفوظة دون حذف.
- موصل FullEnrich v2 جاهز محليًا؛ تشغيله الحقيقي يحتاج مفتاحًا وصلاحية Search API ورصيدًا. لم يُنفذ طلب حي أثناء التطوير.
- القوائم الحالية تشمل 8 مجموعات قطاعات و4 بلدان فقط؛ ليست ادعاء بتغطية كل القطاعات أو الشبكات. تخضع النتائج لتغطية المزود.
- مساعد الاستهداف محاكاة بالكلمات المفتاحية، وليس اتصالًا بنموذج AI.
- إنشاء روابط الدعوات يعمل؛ إرسالها تلقائيًا بالبريد غير متصل.
- ملف CSV اختبر محليًا ونزّل من المتصفح؛ لم يختبر داخل حساب GoHighLevel حي.
- التخزين الحالي SQLite محلي، بديل مؤقت لتشغيل المعاينة دون حسابات سحابية. تكامل Supabase Auth/Postgres وسياسات RLS من الخطة الأصلية لم ينفذ بعد.
- البحث الحقيقي محدود بعشرة أشخاص في دفعة واحدة. تحفظ المنصة رقم الإثراء وتتابعه عند فتح صفحة النتائج؛ لا عامل خلفي مستقل ولا webhook. الطلب ذو الاستجابة المفقودة لا يُرسل مجددًا تلقائيًا.
- لا يوجد نشر عام أو دومين أو مراجعة إنتاجية. التطبيق يرفض API خارج اسم مضيف محلي أو عند غياب APP_MODE=demo.

## هيكل التطبيق

- src/app: صفحات Next.js ومسار API.
- src/components: الواجهات المشتركة، الدخول، المشترك، والأونر.
- src/lib/contracts.ts: مدخلات البحث وأنواع البيانات.
- src/lib/demo-provider.ts: الكتالوج المحلي والمساعد التجريبي.
- src/lib/store.ts: التخزين والمعاملات والجلسات والدعوات.
- src/lib/csv.ts: تصدير CSV الآمن.
- tests/store.test.ts: اختبارات السلوك والرصيد والعزل.
- .data/wasl.sqlite: قاعدة البيانات المحلية، غير مخصصة للإيداع أو النشر.
- .env.local: إعداد المعاينة، غير مخصص للإيداع.

## التحقق

- node --import tsx --test tests/*.test.ts: 31 اختبارًا وظيفيًا ومحاكاة تكامل تشمل التزامن والتكرار، فشل المزوّد، التراجع الكامل عن المعاملة الفاشلة، الدعوات والجلسات، عزل التصدير، حالة البريد في CSV، واستمرار البيانات بعد إعادة الفتح.
- npm run lint: فحص جودة الشفرة.
- npm run typecheck: فحص الأنواع.
- npm run build: بناء التطبيق.

اختبار المتصفح شمل الدخول كمشترك، البحث وتسليم 10 عناوين وهمية، خصم 10 كريدت، تنزيل CSV، اقتراح معايير من وصف، وإنشاء دعوة وقبولها برصيد 25 كريدت. هذه أدلة تشغيل محلي وليست أدلة لربط خدمات خارجية.

## قبل الانتقال إلى الإنتاج

1. اعتماد الاسم واللغة والهوية.
2. اختيار مزود بيانات مرخص للعرض والتخزين والتصدير إلى المشتركين، واختبار جودته وكلفة التسليم.
3. تهيئة Supabase/Auth/RLS وعزل الحسابات على قاعدة تجربة، ثم تكرار اختبارات الرصيد والتزامن والعزل عليها.
4. نقل مصدر البيانات إلى موصل حي، وإضافة دورة مهام متينة بحسب طبيعة API، والتحقق من معيار البريد المقبول.
5. توصيل AI الحقيقي والبريد التشغيلي مع حدود إنفاق ومراقبة.
6. اختبار استيراد CSV في GoHighLevel، وسياسة الاحتفاظ والحذف والاسترجاع والنسخ الاحتياطي.
7. إزالة مسارات دخول/تبديل الحسابات التجريبية من نسخة الإنتاج، ثم اختبارها ونشرها بعد تجهيز حسابات العميل.

سعر التطوير المتفق عليه للنسخة الأولى: 4,000 دولار. فواتير الخدمات والبيانات والتشغيل منفصلة.

## تحديث 24 سبتمبر — الداشبورد فقط

أُنجز P1.1/P1.2: ملخص محدود وإحصاءات مستقلة، مع 18 اختباراً وبناء وفحص شفرة ناجحين. التقرير في docs/performance.md. GET /api/bootstrap يرجع الملخص افتراضياً؛ view=full يحافظ مؤقتاً على عقد صفحات القوائم حتى مهام تقسيمها. days اختياري: ثمانية حدود ISO لسبعة أيام حسب توقيت المتصفح.

انخفض جسم رد داشبورد المشترك من 5.5 MB إلى 3 KB على عينة معزولة من 100,000 جهة و1,000 مشترك. الأرقام ليست اختبار تحمل متزامن. كود الطابور السابق ما زال جزئياً وغير متصل بعامل مستقل. لم تنفذ مرحلة الحماية أو الربط الخارجي في هذا التحديث.
